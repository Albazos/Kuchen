\section{Projektuebersicht}

\textbf{KuchenApp} ist eine Desktop-Anwendung, die im Rahmen eines Schulprojekts
(Berufsschule, Fachinformatiker Anwendungsentwicklung) entwickelt wurde. Die Anwendung
dient zur Verwaltung einer Kuchen-Liste fuer eine Schulklasse und ermoeglicht den
automatisierten Versand von Erinnerungs-E-Mails ueber das IServ-System.

\subsection{Funktionsumfang}

\begin{itemize}[leftmargin=1.5em]
    \item CSV-Dateien importieren, bearbeiten und speichern
    \item Dynamische Tabellendarstellung mit Sortier- und Suchfunktion
    \item Aufsteigende und absteigende Sortierung per ComboBox-Auswahl
    \item Verwaltung einer Empfaenger-Mailliste (separater Dialog)
    \item Automatische HTML-Tabellengenerierung fuer E-Mail-Inhalte
    \item E-Mail-Versand ueber IServ-SMTP mit editierbarem Subject
    \item INI-basierte Einstellungsverwaltung
    \item Zentrales Dark-Blue-Theme ueber externe QSS-Datei
    \item Standalone-Build fuer Linux und Windows (PyInstaller)
    \item CI/CD ueber GitHub Actions mit automatischem Release
\end{itemize}

        Standard-Headern ausgeliefert.

\begin{warnbox}[Hinweis zu Standard- und lokalen Daten]
Im Repository sollten nur neutrale Template-Dateien versioniert werden. Reale
Nutzdaten aus dem schulischen Alltag koennen lokal weiterverwendet werden,
sollten aber fuer ein oeffentliches Repository nicht eingecheckt werden.
\end{warnbox}

\section{Architektur und Entwurfsmuster}

\subsection{Gesamtarchitektur}

Die Anwendung folgt einer \textbf{Schichtenarchitektur}:

\begin{tcolorbox}[
    colback=white, colframe=primary!50,
    boxrule=0.5pt, arc=3pt,
]
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Praesentationsschicht} -- GUI-Klassen (\texttt{CMainWindow},
        \texttt{CKuchenDialog}, \texttt{CLoginDialog}), Qt-UI-Dateien
    \item \textbf{Logikschicht} -- Datenverarbeitung (\texttt{DataManager}),
        Einstellungen (\texttt{SettingsManager}), Mail-Versand
        (\texttt{IservMailManager})
    \item \textbf{Datenzugriffsschicht} -- CSV-Dateien, INI-Konfiguration,
        IServ-SMTP-API
\end{enumerate}
\end{tcolorbox}

\subsection{Verwendete Entwurfsmuster}

\subsubsection{Singleton-Pattern (AppLogger)}

Der \texttt{AppLogger} implementiert das \textbf{Singleton-Pattern} ueber Pythons
\texttt{\_\_new\_\_}-Methode. Damit existiert waehrend der gesamten Laufzeit
exakt eine Logger-Instanz.

\begin{infobox}[Fachliche Begruendung]
Alle Klassen sollen Fehlermeldungen an die GUI weiterleiten koennen, ohne eine
Referenz auf das Hauptfenster zu benoetigen. Der Singleton stellt sicher, dass
alle \texttt{AppLogger()}-Aufrufe dieselbe Instanz zurueckgeben und somit die
gleichen Qt-Signale nutzen.
\end{infobox}

\begin{lstlisting}[language=Python, caption={Singleton-Implementierung}]
class AppLogger(QObject):
    errorOccurred = Signal(str, str)
    warningOccurred = Signal(str, str)
    infoOccurred = Signal(str, str)

    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self):
        if not hasattr(self, '_initialized'):
            super().__init__()
            self._initialized = True
\end{lstlisting}

\subsubsection{Observer-Pattern (Qt Signal/Slot)}

Die Kommunikation zwischen den Schichten erfolgt ueber das
\textbf{Observer-Pattern}, implementiert durch Qt's Signal/Slot-Mechanismus.

\begin{itemize}[leftmargin=1.5em]
    \item \texttt{AppLogger} emittiert Signale (\texttt{errorOccurred},
        \texttt{warningOccurred}, \texttt{infoOccurred})
    \item \texttt{CMainWindow} verbindet diese mit Slot-Methoden, die
        \texttt{QMessageBox}-Dialoge anzeigen
    \item \texttt{QStandardItemModel.dataChanged} benachrichtigt bei
        Zellenaenderungen in der Tabelle
\end{itemize}

\begin{infobox}[Fachliche Begruendung]
Lose Kopplung -- der \texttt{DataManager} und \texttt{IservMailManager}
kennen die GUI nicht, sondern kommunizieren ueber den \texttt{AppLogger}.
Dies ermoeglicht eine saubere Trennung der Schichten.
\end{infobox}

\subsubsection{Model-View-Pattern (Qt MVC)}

Die Tabellendarstellung nutzt Qt's \textbf{Model-View}-Architektur:

\begin{table}[ht!]
\centering
\rowcolors{2}{codebg}{white}
\begin{tabularx}{0.85\textwidth}{lX}
\toprule
\textbf{Rolle} & \textbf{Implementierung} \\
\midrule
Model & \texttt{QStandardItemModel} -- haelt die Tabelleneintraege \\
View & \texttt{QTableView} -- zeigt die Daten an \\
Controller & Window-Klasse vermittelt zwischen \texttt{DataManager} und Model \\
\bottomrule
\end{tabularx}
\end{table}

\section{Module im Detail}

\subsection{KuchenMain.py -- Hauptfenster}

\texttt{CMainWindow} erbt von \texttt{QMainWindow} und \texttt{Ui\_MainWindow}
(Multiple Inheritance, empfohlener Qt-Ansatz). Es ist der \textbf{Entry Point}
der Anwendung.

\begin{description}[style=nextline, leftmargin=1.5em]
    \item[\texttt{\_createRadioButtons()}]
        Befuellt die Sortier-ComboBox dynamisch mit allen aktuellen CSV-Headern.
    \item[\texttt{SortColumn()}]
        Liest die ausgewaehlte Spalte aus \texttt{cmbSortField} sowie die
        Richtung aus \texttt{cmbSortDirection} und ruft
        \texttt{DataManager.sortData()} entsprechend auf.
    \item[\texttt{Search(aText)}]
        Filtert die Originaldaten (\texttt{mData}) nach dem Suchbegriff.
        Ist in der Sortier-ComboBox eine Spalte ausgewaehlt, wird nur in der
        entsprechenden Spalte gesucht. Ansonsten: Volltextsuche ueber alle Spalten.
        Nach dem Filtern wird die Sortierung erneut angewandt.
    \item[\texttt{CellEdited(aItem)}]
        Aktualisiert den bearbeiteten Tabellenwert in \texttt{mSortedData}.
        Da die gefilterten und sortierten Ansichten auf dieselben Zeilenobjekte
        wie die Originaldaten verweisen, bleibt \texttt{mData} dabei konsistent.
    \item[\texttt{FillTable()}]
        Loescht das \texttt{QStandardItemModel}, setzt Header und fuellt die
        Tabelle aus \texttt{mSortedData}. Aktualisiert zusaetzlich die
        Metaanzeige mit der Anzahl der Eintraege.
    \item[\texttt{SendMails()}]
        Zeigt einen Bestaetigungsdialog mit der Empfaengeranzahl, oeffnet den
        Login-Dialog und wertet den Tri-State-Rueckgabewert aus
        (\texttt{None}=abgebrochen, \texttt{True}=gesendet,
        \texttt{False}=fehlgeschlagen).
    \item[\texttt{\_load\_app\_theme()}]
        Laedt die zentrale Datei \texttt{theme\_dark\_blue.qss}, ersetzt den
        Platzhalter fuer den Asset-Pfad und bindet das Theme global in die
        QApplication ein.
    \item[\texttt{ImportFile()}]
        Oeffnet einen \texttt{QFileDialog}, importiert die CSV und
        aktualisiert die Sortier-ComboBox dynamisch anhand der neuen Header.
\end{description}

\begin{warnbox}[PyInstaller-Kompatibilitaet]
Im \texttt{\_\_main\_\_}-Block wird \texttt{sys.frozen} geprueft, um den
Icon-Pfad korrekt aufzuloesen (\texttt{sys.\_MEIPASS} im Bundle vs.
\texttt{\_\_file\_\_} im Entwicklungsmodus).
\end{warnbox}


\subsection{DataManager.py -- Datenverwaltung}

Der \texttt{DataManager} ist die zentrale Klasse fuer alle Datenoperationen.
Er verwaltet zwei unabhaengige Datensaetze:

\begin{table}[ht!]
\centering
\rowcolors{2}{codebg}{white}
\begin{tabularx}{0.85\textwidth}{lX}
\toprule
\textbf{Datensatz} & \textbf{Attribute} \\
\midrule
Haupttabelle (Kuchen) & \texttt{mData}, \texttt{mSortedData}, \texttt{mMainHeaders} \\
Mail-Tabelle (Empfaenger) & \texttt{mMailData}, \texttt{mSortedMailData}, \texttt{mMailHeaders} \\
\bottomrule
\end{tabularx}
\end{table}

\begin{infobox}[Duale Datenhaltung]
\texttt{mData} enthaelt immer die \emph{unsortierten} Originaldaten.
\texttt{mSortedData} ist eine gefilterte/sortierte Kopie, die in der Tabelle
angezeigt wird. Dies ermoeglicht das Zuruecksetzen von Sortierung und Suche.
\end{infobox}

\textbf{Schluesselfunktionen:}

\begin{description}[style=nextline, leftmargin=1.5em]
    \item[\texttt{LoadStandardFile(aForMainTable)}]
        Laedt die CSV-Datei, deren Name in den Settings steht. Verwendet
        \texttt{csv.Sniffer} zur automatischen Dialekt-Erkennung (Trennzeichen,
        Quoting). Extrahiert die erste Zeile als Header und merkt sich das
        erkannte Trennzeichen fuer spaeteres Speichern.
    \item[\texttt{ImportFile(aPath)}]
        Importiert eine externe CSV. Speichert den Dateinamen getrennt fuer
        Haupt- und Maildaten, damit beim naechsten \texttt{SaveFile()} der
        passende Name in die Settings uebernommen wird.
    \item[\texttt{SaveFile(aForMainTable)}]
        Speichert die Daten als CSV. Wurde zuvor eine Datei importiert,
        aktualisiert \texttt{SaveFile} automatisch die Settings mit dem
        neuen Dateinamen und behaelt das urspruenglich erkannte Trennzeichen bei.
    \item[\texttt{sortData(aSortColumnIndex, aReverse, aForMain)}]
        Sortiert \texttt{mSortedData} nach der gegebenen Spalte.
        Der Parameter \texttt{aReverse} steuert die Richtung.
    \item[\texttt{\_padRows(aData, aHeaderLen)}]
        Fuellt Datenzeilen mit leeren Strings auf, falls sie weniger Spalten
        als der Header haben -- Robustheit beim Import unvollstaendiger CSVs.
    \item[\texttt{createCompleteMailData()}]
        Bereitet Mail-Daten auf: extrahiert E-Mail-Adressen und generiert
        einen HTML-String der Kuchen-Tabelle fuer den E-Mail-Body.
    \item[\texttt{createHtmlDataString()}]
        Erzeugt eine formatierte HTML-Tabelle mit Inline-CSS. Verwendet
        \texttt{html.escape()} zur Vermeidung von XSS-Schwachstellen.
\end{description}


\subsection{SettingsManager.py -- Einstellungsverwaltung}

Verwaltet die Anwendungseinstellungen in einer INI-Datei
(\texttt{Data/Settings/settings.ini}) ueber Pythons \texttt{configparser}-Modul.

\begin{lstlisting}[language={}, caption={settings.ini -- Konfigurationsstruktur}]
[Klassen]
Dateiname = StandardKlasse.csv

[CakeData]
Dateiname = StandardCakeData.csv

[IServ]
Domain = example.org
\end{lstlisting}

\begin{infobox}[Default-Werte]
Die Klasse definiert ein \texttt{\_DEFAULTS}-Dictionary. Beim Instanziieren
werden zuerst die Defaults geladen, dann die INI-Datei daruebergelegt. So
sind immer Fallback-Werte vorhanden.
\end{infobox}


\subsection{AppLogger.py -- Singleton-Logger}

Implementiert das Singleton-Pattern (siehe Abschnitt 3.2.1). Stellt drei
Schweregrade bereit:

\begin{table}[ht!]
\centering
\rowcolors{2}{codebg}{white}
\begin{tabularx}{0.85\textwidth}{llX}

\midrule

\subsection{KuchenMailManager.py -- Mail-Listen-Dialog}

\texttt{CKuchenDialog} ist ein modaler Dialog (\texttt{QDialog}) zur Verwaltung
der Empfaenger-Mailliste. Er teilt sich den \texttt{DataManager} mit dem
Hauptfenster und arbeitet auf den Mail-Daten (\texttt{mMailData}).

Die Funktionalitaet ist analog zum Hauptfenster: Sortierung per ComboBox,
Suche, Import, Speichern, Zeilen hinzufuegen/loeschen und zentrale Theme-Nutzung.
Der Button \texttt{pbnAddColumn} ist bereits in der Oberflaeche vorhanden,
loggt derzeit aber nur, dass die Funktion noch nicht implementiert ist.


\subsection{LoginDialog.py -- IServ-Login}

\texttt{CLoginDialog} ist ein modaler Dialog fuer die SMTP-Authentifizierung.
Der Dialog zeigt zusaetzlich die Empfaengeranzahl und ein editierbares
Subject-Feld an.

\begin{successbox}[Tri-State-Logik]
\begin{itemize}[leftmargin=1.5em, nosep]
    \item \texttt{mSendState = None} -- Benutzer hat abgebrochen
    \item \texttt{mSendState = True} -- Mails erfolgreich gesendet
    \item \texttt{mSendState = False} -- Fehler beim Senden (Dialog bleibt offen)
\end{itemize}
\end{successbox}


\subsection{IservMailManager.py -- Mail-Versand}

Erstellt eine Verbindung zur IServ-API und sendet E-Mails ueber SMTP\_SSL.
Das Passwort wird im \texttt{finally}-Block auf \texttt{None} gesetzt,
um es nicht unnoetig im Speicher zu halten.

Der Mail-Subject wird nicht mehr fest verdrahtet, sondern aus dem Login-Dialog
uebernommen. Ist das Subject-Feld leer, wird auf \texttt{"Kuchen reminder"}
zurueckgefallen.

Fehlerbehandlung faengt spezifische Exceptions:
\texttt{OSError}, \texttt{smtplib.SMTPException}, \texttt{ValueError},
\texttt{ConnectionError}.

\section{Datenpersistenz}

\subsection{CSV-Format}

Die Anwendung speichert Daten als CSV-Dateien (Comma-Separated Values).
Beim Laden wird \texttt{csv.Sniffer} zur automatischen Erkennung des
Trennzeichens verwendet -- so werden sowohl Komma- als auch
Semikolon-getrennte Dateien korrekt gelesen.

\begin{lstlisting}[language={}, caption={StandardCakeData.csv -- Header-Vorlage}]
Name,CakeCount,Hanuta,Waffel,Date
\end{lstlisting}

\begin{infobox}[Dynamische Header]
Die Header werden nicht hartcodiert, sondern aus der ersten Zeile der CSV-Datei
gelesen. Die GUI befuellt ihre Sortier-ComboBoxen dynamisch aus diesen
Headern.
\end{infobox}

\subsection{Settings (INI)}

Einstellungen werden ueber Pythons \texttt{configparser}-Modul in einer
INI-Datei verwaltet. Die Datei wird mit Defaults initialisiert und bei
Aenderungen (z.\,B. Import einer neuen CSV) automatisch aktualisiert.

\section{Build-System und CI/CD}

Das Build-System ist zweigeteilt: \textbf{lokal} wird nur das Source-Bundle
erstellt, \textbf{Standalone-Builds} fuer Linux und Windows laufen
ausschliesslich ueber GitHub Actions.

\subsection{build\_release.py -- Lokaler Build}

\begin{codebox}[Verwendung]
\begin{lstlisting}[language=bash, numbers=none]
python build_release.py           # Release-Ablauf mit Versionssprung
python build_release.py --source  # Nur Source-Bundle bauen
python build_release.py --standalone  # Standalone fuer aktuelles OS bauen
\end{lstlisting}
\end{codebox}

\textbf{Ablauf bei normalem Aufruf ohne Flags:}
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Version:} Patch-Version in \texttt{version.ini} wird erhoeht
    \item \textbf{Clean:} Alter \texttt{release/}-Ordner wird geloescht
    \item \textbf{UI-Kompilierung:} \texttt{.ui} $\rightarrow$ \texttt{\_ui.py}
        via \texttt{pyside6-uic}
    \item \textbf{Kopieren:} Quelldateien in die Release-Struktur
    \item \textbf{README:} Automatische README.txt-Generierung
    \item \textbf{ZIP:} Source-Bundle als \texttt{KuchenApp.zip}
    \item \textbf{Release:} Git- und GitHub-Release-Ablauf mit Upload der Artefakte
\end{enumerate}

\subsection{PyInstaller -- Standalone-Builds}

PyInstaller verpackt Python-Interpreter, PySide6 und alle Quelldateien in
eine einzelne ausfuehrbare Datei. Die Standalone-Builds werden
\textbf{nur in der CI-Pipeline} ausgefuehrt.

\begin{table}[ht!]
\centering
\rowcolors{2}{codebg}{white}
\begin{tabularx}{0.85\textwidth}{lX}
\toprule
\textbf{Option} & \textbf{Bedeutung} \\
\midrule
\texttt{--onefile} & Einzelne Datei statt Ordner \\
\texttt{--windowed} & Kein Konsolenfenster (GUI-App) \\
\texttt{--add-data} & Icon und Data-Verzeichnis einbetten \\
\bottomrule
\end{tabularx}
\end{table}

\textbf{Laufzeit-Pfadaufloesung:} Da PyInstaller Dateien in ein temporaeres
Verzeichnis (\texttt{sys.\_MEIPASS}) entpackt, aber \texttt{Data/}
beschreibbar sein muss, wird \texttt{Data/} neben die Executable kopiert:

\begin{lstlisting}[language=Python, caption={Pfadaufloesung fuer PyInstaller}]
def _get_base_dir():
    if getattr(sys, 'frozen', False):
        return os.path.dirname(sys.executable)
    return os.path.dirname(os.path.dirname(
        os.path.abspath(__file__)))
\end{lstlisting}


\subsection{GitHub Actions -- CI/CD-Pipeline}

Der Workflow \texttt{.github/workflows/build\_release.yml} baut automatisch
fuer beide Betriebssysteme.

\begin{successbox}[Pipeline-Uebersicht]
\begin{tabularx}{\textwidth}{lX}
\textbf{Trigger:} & Version-Tag (\texttt{v*}) \\
\textbf{Jobs:} & Matrix-Build fuer Linux und Windows \\
\textbf{Release:} & Haengt die Standalone-ZIPs an das GitHub Release an \\
\end{tabularx}
\end{successbox}

\textbf{Workflow-Ablauf:}
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Tag-Push} -- der lokale Release-Build erstellt und pusht
        einen Version-Tag (\texttt{v*}).
    \item \textbf{Matrix-Build} -- GitHub Actions baut je eine Standalone-ZIP
        fuer Linux und Windows mit \texttt{build\_release.py -{}-standalone}.
    \item \textbf{Release-Upload} -- der Workflow haengt die Standalone-ZIPs an
        das GitHub Release an.
    \item \textbf{Source-Upload} -- das lokale Skript laedt anschliessend
        \texttt{KuchenApp.zip} zum gleichen Release hoch.
\end{enumerate}

\begin{codebox}[Release ausloesen]
\begin{lstlisting}[language=bash, numbers=none]
python build_release.py
\end{lstlisting}
\end{codebox}

\begin{codebox}[Nur Source-Bundle in der CI oder lokal]
\begin{lstlisting}[language=bash, numbers=none]
python build_release.py --source
\end{lstlisting}
\end{codebox}

\subsection{Bedienung}

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Daten laden:} Beim Start wird die zuletzt verwendete CSV
        automatisch geladen.
    \item \textbf{Import:} Ueber den \emph{Import}-Button kann eine andere
        CSV-Datei geladen werden. Spalten und Sortier-ComboBox passen
        sich automatisch an.
    \item \textbf{Bearbeiten:} Zellen koennen direkt in der Tabelle
        bearbeitet werden (Doppelklick).
    \item \textbf{Zeilen hinzufuegen/loeschen:} Ueber die Buttons
        \emph{+ New entry} und \emph{Delete}.
    \item \textbf{Sortierung:} ComboBoxes in der Sidebar.
        \emph{Ascending}/\emph{Descending} waehlt die Richtung.
    \item \textbf{Suche:} Das Suchfeld \emph{Search} filtert live. Bei aktiver
        Sortier-Spalte wird nur in der entsprechenden Spalte gesucht.
    \item \textbf{Speichern:} Ueber den \emph{Save}-Button. Bei importierten
        Dateien wird der neue Dateiname in den Settings gespeichert.
    \item \textbf{Mail-Liste:} Ueber \emph{Open mail list} oeffnet sich
        ein separater Dialog zur Verwaltung der Empfaenger.
    \item \textbf{Mails senden:} Ueber \emph{Send mails}. Es erscheint eine
        Bestaetigung mit der Empfaengeranzahl, dann der Login-Dialog mit
        editierbarem Subject.
\end{enumerate}

\section{Glossar}

\begin{description}[style=nextline, leftmargin=1.5em]
    \item[CSV] Comma-Separated Values -- Tabellenformat mit Trennzeichen
    \item[INI] Initialisierungsdatei -- Einfaches Konfigurationsformat
    \item[PySide6] Offizielle Python-Bindings fuer das Qt 6 Framework
    \item[Qt Designer] Visueller Editor fuer Qt-Oberflaechen (.ui-Dateien)
    \item[PyInstaller] Tool zum Verpacken von Python-Programmen als Standalone
    \item[SMTP\_SSL] Simple Mail Transfer Protocol ueber SSL-Verschluesselung
    \item[Singleton] Entwurfsmuster: Garantiert genau eine Instanz einer Klasse
    \item[Observer] Entwurfsmuster: Objekte werden ueber Zustandsaenderungen
        benachrichtigt (in Qt: Signal/Slot)
    \item[MVC] Model-View-Controller -- Architekturmuster zur Trennung von
        Daten, Darstellung und Steuerung
    \item[CI/CD] Continuous Integration / Continuous Deployment -- Automatisierte
        Build- und Release-Pipelines
    \item[XSS] Cross-Site Scripting -- Sicherheitsluecke durch unescapten
        HTML-Input
    \item[IServ] Schulplattform mit E-Mail, Kalender und Dateiverwaltung
    \item[GitHub Actions] CI/CD-Dienst von GitHub fuer automatisierte Workflows
\end{description}
